# 饿了幺项目说明

## 项目定位

饿了幺是一个 AI 本地生活决策助手微信小程序 MVP。

当前阶段不追求真实 AI 和真实商户数据，重点是跑通可演示闭环：

微信登录 → 首页 → 今天吃什么 → 问答收集偏好 → mock AI 回复 → mock 店铺推荐 → 本地记忆偏好。

## 当前已完成

- 首页入口已完成。
- 「今天吃什么」流程已完成初版。
- 口味标签、需求标签、忌口标签已接入。
- mock 推荐逻辑已能根据标签进行过滤或排序。
- 用户可以看到 2-3 个 mock 推荐方案。

## 开发原则

- 不要删除已有功能。
- 不要大规模重构无关文件。
- 每次只完成一个小任务。
- 修改前先说明计划。
- 修改后说明改了哪些文件、如何测试、潜在风险。
- 标签数据、mock 店铺数据、推荐逻辑尽量独立维护。
- 不引入大型 UI 库。
- 微信小程序优先使用 view、text、button 等原生组件。
- 保持现有项目风格，优先保证小程序可运行。

## 推荐逻辑原则

- avoid 标签用于硬性过滤。
- taste 标签用于推荐加分。
- need 标签用于辅助加分。
- spicyLevel 用于判断辣度。
- 推荐结果至少展示 2-3 个方案卡片。
- 推荐卡片应包含名称、人均、距离、评分、匹配标签、推荐理由、风险提示。

## 当前优先方向

P0：
- 检查首页到「今天吃什么」完整流程是否稳定。
- 检查本地存储是否正常保存最近一次偏好。
- 优化推荐卡片字段展示。
- 确保推荐结果始终有 2-3 个方案。

P1：
- 增加「换一批」。
- 增加「更近一点」。
- 增加「更便宜一点」。
- 丰富 mock 店铺数据，让不同标签能产生明显不同推荐结果。

P2：
- 增加多人约饭流程。
- 增加周末轻规划流程。
- 增加偏好档案页。
