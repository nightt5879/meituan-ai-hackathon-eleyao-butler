## 1. 一句话描述

**在微信小程序里活着一个真正"管事"的 AI 管家，用 OpenClaw 跨工具自主执行，覆盖新一代年轻人一天 24 小时里 3-5 个关键时刻的本地生活需求——不是又一个聊天机器人，是一个会主动提醒、能代替你做事的随身管家。**

---

## 2. 针对什么人群 / 场景

### 虚拟主用户画像（我们主要为这个人设计）

- **名字**：小林，26 岁，上海独居合租
- **身份**：互联网公司运营，工作 2 年
- **生活特征**：
  - 时间碎片，白天工作强度高，下班后疲惫但还想把生活过好
  - 对"做选择"累了——早餐选啥、中午吃啥、周末去哪 都是决策消耗
  - AI 原生心智，天天用 ChatGPT / DeepSeek，习惯对着 AI 说话下指令
  - 生活质量诉求：想吃得健康、想偶尔运动、想社交但怕麻烦
- **次级画像**：在读研究生/本科生、刚搬到新城市的年轻白领、情侣/合租室友

### 一天中的 5 个关键时刻（我们只聚焦这 5 个，不贪多）

| 时刻 | 场景 | 痛点 | 管家动作 |
|---|---|---|---|
| **早 7:30** | 起床通勤 | 不想想、又怕出门尴尬 | 根据天气/日程，推早餐 + 通勤方案 + 穿搭提示 |
| **午 12:00** | 午饭决策 | 每天纠结 10 分钟 | "这周吃过啥 + 今天心情 + 预算" → 3 选 1，一键下单 |
| **深夜突发** | 胃痛 / 情绪崩 / 忘带钥匙 | 慌乱 + 没时间查 | 找 24h 药店/就近医院、联系锁匠、紧急闺蜜群聊 |
| **晚 18:30** | 约饭/约会协调 | 两人/三人对齐难 | 多人偏好和预算对齐 → 餐厅推荐 → 一键预订 |
| **周末 9:00** | 周末规划 | "好懒但又不想浪费" | 天气+预算+心情 → 3 条周末路径（出门/宅家/折中） |

**为什么只打这 5 个时刻**：demo 时可以讲成"**小林的一天**"——24 小时叙事线，每个时刻都是 Agent 多工具调用的亮点。比"我们什么都能做"有力 10 倍。

---

## 3. 解决什么痛点

- **决策疲劳**：年轻人一天做 35000 个微决策，"吃啥喝啥去哪"这类低价值决策消耗了大量心智带宽
- **信息过载**：美团/大众点评/小红书/高德/微信/外卖 App 并列打开，交叉比较成本高
- **时间碎片化**：工作学习忙，没整块时间研究和规划
- **突发需求的兜底缺失**：深夜生病、临时叫车、忘带东西——现有 App 都是白天体验，夜间场景弱
- **主动性空白**：现有 AI / 生活服务都是 reactive（你问它答/你下单它送），**没有一个服务会主动说"你该吃饭了"或"你三天没运动了"**——这是我们的核心差异点

## 4. MVP（最小可行版本）

### 输入

用户通过小程序对话框 / 订阅消息 / 周期性触发，向 AI 下达一句话指令，或者 AI 主动 push 一条提示。

### 输出

AI 调用工具链完成任务，在小程序内以卡片/消息形式呈现结果，**关键动作可一键执行**（下单/预订/导航）。

### 具体示例（午饭场景）

**输入**：用户中午 11:50 主动打开小程序

**AI 主动动作**（Proactive Butler）：

> "小林你好，今天上海 26°C 有点闷。你这周已经吃了两次米线、一次麻辣烫，预算还有 120 块午饭可用。我推荐：
> - 🥗 **轻食沙拉**（办公室楼下，评分 4.6，38 元，15 分钟送达）
> - 🍲 **川菜盖饭**（你点过 3 次给过 5 星，52 元，22 分钟送达）
> - 🍝 **新发现：老意面馆**（500 米内，评分 4.7，68 元，你没吃过这家）
> 一键下单请点 →"
>
> 主要还可以体现美团这个生态（讲故事接入美团）

用户点第 3 个 → AI 自动下单 → 生成取餐提醒 → 饭后询问反馈、记忆偏好更新。

### 最核心的那一个功能：**主动性 + 跨工具执行**

这是所有"普通 AI 聊天"做不到的两件事叠加：

1. **主动性**（Proactive）：AI 在关键时刻**主动出现**，不等用户问
2. **跨工具自主执行**（Agentic）：一句话调动多个 Tool，把事情**真的做掉**，不是只回答"你可以这样做"

**这两件事加在一起，才是"全天候私人管家"，而不是"又一个 ChatGPT"**。持久性记忆，能够长期学习了解习惯，而不是一个个web端（打开麻烦，持久记忆，习惯问题）

## 5. 技术方向

### 核心架构

```
用户 (微信小程序 + 订阅消息)
    ↓↑
OpenClaw Agent 中枢 (已部署在云服务器 ← 起跑线优势)
    ↓↑
LLM (Codex / GPT-4o，200$ 订阅) 这个后续可以说明可以替换到他们自己的模型之类的都可以
    ↓
Tool Chain：
  ├── 地图 API (高德/百度等)
  ├── 外卖/餐厅数据 (大众点评开放数据 / 爬虫 cache / 模拟 / 主要讲讲美团生态)
  ├── 天气 API
  ├── 日历 & 提醒
  ├── 记忆模块 (RAG over 用户历史对话和行为)
  ├── 健身/冥想/学习资源索引
  └── 紧急服务索引（24h 药店、急救信息、锁匠）
    ↓
小程序 UI (Taro / uni-app)
```

### 关键技术挑战

**小程序的"全天候"怎么兑现**（这是 v2 最大的技术难点）：

1. **用户主动打开是基础**：UI 和体验要让用户每天愿意打开 3-5 次
2. **订阅消息推送**：每次用户交互后能订阅下一条 push，串起"早提醒 / 午推荐 / 晚关怀 / 周末规划"的循环
3. **绑定服务号 / 公众号**：用模板消息覆盖订阅消息的频率短板（需要做合规性 check，公众号推送可能是相对较好的）  然后这里有一定的点是 可以直接接入微信clawbot，这个的问题是就只能单个人使用，但是效果会好很多（更像一个自动化助手，问题就是测试和开发，只有一个人能接入）
4. **小程序内的"管家时间轴"视图**：让用户可视化看到"管家一直在陪我"——即使没有消息 push，也能感知到存在

| 模块 | 技术 | 负责人 |

| Agent 中枢 | OpenClaw + Codex | （已有基础） |

## 6. 我最想做这个的原因

- **我们就是用户**：队伍 4 个人都在目标画像范围内。dogfood 能做到极致，不是"想象用户"
- **OpenClaw 放对了地方**：它的"跨工具自主执行"能力放在"我们自己每天要用的管家"上，能把 Agent 的价值讲到最清楚
- **"全天候主动管家"是评委没见过的定位**：市面上 AI 都是 reactive 型，只会回答、不会主动；我们做的是"**会主动出现、能真的做事**"
- **战略上**：比赛结束后这个产品我们自己也想继续用——这种"真心做产品"的态度评委感觉得到

## 7. 不确定 / 想问的问题

### 技术类

- **小程序订阅消息的频率**够不够支撑我们要的"每天 3-5 次主动 push"？如果不够，**绑定服务号走模板消息**是否可行？
- 小程序**个人注册**能不能接入订阅消息 + 服务号？还是必须企业主体？这是一个**必须第一周搞清楚**的 blocker
- 大众点评 / 外卖 / 地图 数据源：哪些能拿到真实 API，哪些必须 mock？mock 数据的量要多少才够 demo 真实感？
- 到底要不要直接用微信的clawbot

### 产品类

- **5 个场景是不是还是太多**？要不要缩到 3 个（午饭 / 晚饭社交 / 周末规划）？
- **"主动 push" 要不要做到 demo 里**？如果做，demo 那天得是事先在某个时间点触发给评委看——技术要求更高，但效果炸裂
- **"管家人设"要不要做**？（比如"小美是你的专属生活管家"——有名字、语气、甚至头像）这会增加用户粘性但加产品工作

### 评审类

- 官方每题的**详细 brief** 我们还没拿到，如果 brief 里有"必须做 XX 功能"的硬要求，我们现在的方向可能要调整——**获取 brief 是优先级最高的事**
- 决赛答辩是 demo 形式为主，还是技术路演为主？这影响我们 MVP 重心
