## 2. 针对什么人群 / 场景

> 谁会用？在什么情况下用？越具体越好，别写"所有人"。  
> 示例：城市通勤族、大学生群体、外卖骑手、夜间打车用户、宝妈、独居老人……

**目标用户**：特种兵外地游客、本地上学的外地大学生、周末想避开人流出行的本地人...

核心目标用户：来本地旅游或短暂停留的年轻人，包括特种兵游客、异地大学生、周末短途出游人群
扩展目标用户：希望避开热门景点、追求轻松周边游的本地居民或家庭用户

**使用场景**：
特种兵出游场景：用户时间有限，希望在最短时间内打卡多个高价值景点，同时兼顾美食体验，并保证按时返回酒店、车站或机场。
城市深度探索场景：用户不追求高强度打卡，而是希望用更轻松的方式体验本地特色，获得适合 citywalk 的路线和高性价比本地美食推荐。
周末避峰出游场景：用户希望避开热门网红地点，在周末找到人流较少、风景较好、适合放松的周边游路线，并根据同行人群情况获得个性化建议。
例子：
①特种兵游客：需要在短时间内完成多景点打卡，自己做攻略很麻烦，网上信息过载难以分辨，使用该模型可以根据游客需求提供最高效最省时的出行办法，包括经典的打卡景点、交通方式、出行时间等，同时用户还可以提出要求，例如重点想玩什么项目、打卡什么建筑，模型可以根据这些信息对路线进行进一步调整，并为客户提供更多游览信息，例如表演、景点关门时间、美食推荐等，帮助用户轻松规划旅游路线。

②本地上学的外地大学生：不要求短时间逛完所有景点，针对这部分用户，可以规划较为轻松的出行路线，根据客户需要推荐多条citywalk路线以及当地特色的平价美食，满足此类用户对本地的深度探索的需求。

③周末想避开人流出行的本地人：不喜好网红打卡点，单纯是周末想去户外走走，不喜欢人流量太大的地方。针对此类用户可以推荐周边自然风景好且人流量少的地方（看看能不能加一个客流量检测的模块，对景点客流量进行实时监控），且因为该类用户一般在一个地方玩的比较久而且大概率是以家庭为单位出行，可以根据家庭组成来进行个性化推荐（比如有老人、小孩这样的家庭肯定和只有夫妻两个的家庭去的地方会有差异，而且对饮食的需求也有不同）

感觉可以出几个模式：特种兵模式、citywalk模式、周边游模式、购物模式等等，然后推荐食物的时候也可以根据用户的喜好来推荐（比如吃辣不吃辣、吃火锅还是烧烤、是否想吃正宗本地菜等等，美团本身有这种作为平台的属性，这个对它来说不难而且可以更好的融合）

## 3. 解决什么痛点

> 这些用户现在遇到什么问题？现有方案（美团 APP、大众点评、小红书等）哪里不够好？  
> 不用很完整，写 1-3 条你观察到的痛点就行。

痛点 1：出行决策信息过载，用户筛选成本高。
外地游客或对本地不熟悉的用户在做出行计划时，往往需要同时查看小红书、地图、美团、大众点评等多个平台，信息数量多但分散，难以快速判断哪些景点真正值得去、哪些路线更合理，也容易被热门攻略带偏，导致扎堆出行、体验下降。

痛点 2：现有平台以信息推荐为主，缺少完整的一站式路线规划。
目前大多数平台更擅长提供零散的景点、美食或娱乐场所推荐，但很少能根据用户的时间、地点、预算、返程时间、同行人群等条件，直接生成一套可执行的个性化出行方案，用户仍然需要自己手动拼接路线。

痛点 3：攻略制作过程繁琐，灵活调整成本高。
用户在规划行程时，通常还要额外考虑营业时间、交通时间、景点顺序、吃饭地点、返程安排等细节，过程复杂且耗时；一旦需求变化，例如临时想少走路、换餐厅、提前返程，就需要重新搜索和调整，使用体验不够灵活。

## 4. MVP（最小可行版本）长什么样

> 如果只做出核心功能的最简版本，会是什么样？能用一句话说清"输入什么 → 输出什么"更好。  
> 示例：输入"周六下午 3 小时 + 100 元预算 + 想放松"，输出 3 条完整的周末路线（含交通、餐饮、活动）。

**输入**：指定模式“特种兵模式”，加上要求“打卡海珠区3-4个最值得去的景点+吃到正宗粤菜+20：00前回到酒店”

**输出**：三条路线，包括3个景点的方案和4个景点的方案，并规划好返程路线，保证在20：00前回到指定地点。用户可在此基础上对路线进行进一步要求。

**最核心的那一个功能**：用户输入出行需求与限制条件后，系统自动生成多条可执行的个性化路线方案，覆盖景点顺序、交通方式、餐饮推荐和返程安排，并支持进一步调整。

## 5. 大概的技术方向

> 不用很精确，能猜多少写多少。  
> 可选：前端 / 后端 / 数据 / 算法 / 大模型 / Agent / RAG / 推荐系统 / 小程序 / 网页 / APP

**主要涉及的技术**：

前端：网页或小程序，用于用户输入出行需求、选择模式、查看路线结果
后端：负责接收用户需求，调用地图 API、大模型 API，并完成路线生成与结果整合
数据：景点、餐饮、商圈、营业时间、评分、标签等基础数据存储
推荐系统：根据用户偏好、出行模式、时间预算、同行人群进行个性化筛选和排序
路径规划算法：结合地图 API 计算景点之间的距离、交通时间和整体路线可行性
大模型 / Agent：理解用户自然语言需求，自动拆解条件，并生成可读性强的个性化行程方案
RAG（可选）：如果后期加入本地旅游攻略、商圈信息、特色美食知识库，可通过 RAG 提升回答质量

**是否需要调用外部数据或 API**（例如美团开放接口、地图 API、第三方大模型）：

地图 API：如高德地图 API / 百度地图 API，用于地点搜索、路径规划、出行时间计算、周边推荐
大模型 API：如通义千问、DeepSeek、智谱或 OpenAI，用于理解用户需求并生成路线说明
本地生活/点评类数据：如景点评分、餐厅标签、营业时间、人气信息等，可通过公开平台信息或自建数据集实现
客流量相关数据（可选）：如地图热力图、热门时段数据，用于辅助判断景点拥挤程度并进行避峰推荐
